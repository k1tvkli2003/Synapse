# Execution Plan

## Outcome

Rebuild Synapse into an English-first, Persian-native Flutter Medical Learning OS whose primary loop is a course/chapter/lesson curriculum with Duolingo-grade clarity, progression, feedback, character, and retention mechanics—while preserving and coherently expanding every current Synapse capability and fully absorbing StudyHUB.

`37-goal-charter-v2.md` now carries Goal Charter v3 and is the binding execution overlay. It keeps the Capability Masterpiece Gate, shared Data Plane, root/Content Lead ownership boundary, skill program, and release-truth definition while directing approximately 90% of current execution to the unified Academy Guided Path plus contextual Study Workspace. It does not replace the dependency-checked 440 WBS rows or weaken preservation.

**Current identity authority:** WMR2-01 Warm Living Fold plus the restored LUMA Character System and ICR2-01 LUMA Facefront. MCR4-01/ICR4-04 are historical reproducibility evidence only. The former dental-association concern is an explicit blind-association/real-host review gate, not permission to retain the superseded identity.

## Delivery Strategy

1. Freeze evidence and operational contracts before visual or structural change.
2. Make medical education the additive domain and navigation spine.
3. Use the Harrison-like source first to freeze identity and hierarchy, then atomize every source detail into reviewed segmentation candidates and traceable content packs; never fabricate stable identity, silently drop atoms, or publish raw/generated bodies.
4. Keep stable IDs/routes/data behind adapters while the presentation becomes Today/Path/Clinical/Rounds/You.
5. Generate and select the product/brand/mascot direction before shell implementation.
6. Prove one end-to-end Medical Academy vertical slice before expanding breadth.
7. Build mastery, scheduling, and rewards as authoritative domain systems rather than UI counters.
8. Absorb existing modules and StudyHUB capability-by-capability into contextual workflows.
9. Harden clinical trust, security, privacy, offline behavior, accessibility, performance, and six-platform release paths.
10. Run the explicit `$perfect` critique/fix/verify loop until completion gates are genuinely satisfied.
11. Treat every feature as incomplete until its contextual placement, Night Shift craft, full state model, EN/FA/RTL, accessibility, Full/Reduced/Off motion, Data Plane, performance, and runtime evidence gates pass.
12. Create each project-specific skill only when its real contracts and fixtures exist; validate and forward-test it before relying on it as execution authority.

## Risk Strategy

- Preserve before replace; expand before migrate; shadow-read before activate.
- Quarantine uncertainty rather than infer permanent identity.
- Separate learning evidence from reward and clinical claims.
- Keep all client input untrusted for rewards, publication, staff roles, and canonical content.
- Keep map and semantic outline equivalent.
- Keep Study and Clinical lenses visibly distinct.
- Treat English/Persian, compact/expanded, online/offline, and assistive states as design inputs, not final patches.
- Treat native artifact/runtime proof as part of implementation, not release-week cleanup.
